🪝 Hooks: Automacao de Eventos

Hooks permitem executar codigo personalizado em resposta a eventos do Claude Code. Automatize validacoes, notificacoes e integracoes sem intervencao manual.

🎣 O que sao Hooks

Hooks sao pontos de extensao que permitem executar scripts ou comandos em momentos especificos do fluxo de trabalho do Claude Code. Similar a Git hooks, eles reagem a eventos automaticamente.

🔄 Fluxo de Eventos 

┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   EVENTO    │ →  │    HOOK     │ →  │    ACAO     │
│ (pre-edit)  │    │ (seu script)│    │ (continua   │
│             │    │             │    │  ou bloqueia)│
└─────────────┘    └─────────────┘    └─────────────┘
  • • pre-*: Executam ANTES da acao (podem bloquear)
  • • post-*: Executam DEPOIS da acao (para notificacoes)

📊 Hooks Disponiveis

Pre-hooks

  • • pre-edit - antes de editar arquivo
  • • pre-bash - antes de executar bash
  • • pre-session - inicio de sessao

Post-hooks

  • • post-edit - depois de editar
  • • post-bash - depois de bash
  • • post-session - fim de sessao
2

⚙️ Configurando Hooks

Hooks sao configurados no arquivo settings.json ou em .claude/hooks/ do projeto.

Configuracao via settings.json

{
  "hooks": {
    "pre-edit": {
      "command": ".claude/hooks/validate-edit.sh",
      "timeout": 5000,
      "failOnError": true
    },
    "post-edit": {
      "command": ".claude/hooks/notify-edit.sh",
      "timeout": 3000,
      "failOnError": false
    }
  }
}

Estrutura de Hooks por Projeto

.claude/
└── hooks/
    ├── pre-edit.sh      # Validacao antes de editar
    ├── post-edit.sh     # Notificacao apos editar
    ├── pre-bash.sh      # Validacao antes de bash
    └── post-session.sh  # Cleanup ao finalizar

command

Script ou comando a executar

timeout

Tempo maximo em ms (padrao: 5000)

failOnError

Bloquear acao se hook falhar

✍️ Hook pre-edit: Validacao

O hook pre-edit e executado antes de Claude editar qualquer arquivo. Use para validar, fazer backup ou impedir edicoes indesejadas.

Exemplo: Proteger arquivos criticos

#!/bin/bash
# .claude/hooks/pre-edit.sh
# Variaveis recebidas: $CLAUDE_FILE, $CLAUDE_ACTION

PROTECTED_FILES=(
  "package-lock.json"
  ".env"
  ".env.production"
  "prisma/migrations/*"
)

for pattern in "${PROTECTED_FILES[@]}"; do
  if [[ "$CLAUDE_FILE" == $pattern ]]; then
    echo "BLOQUEADO: $CLAUDE_FILE e um arquivo protegido"
    exit 1  # Exit 1 = bloqueia a acao
  fi
done

echo "OK: Edicao permitida em $CLAUDE_FILE"
exit 0  # Exit 0 = permite a acao

Exemplo: Backup automatico

#!/bin/bash
# Criar backup antes de cada edicao

BACKUP_DIR=".claude/backups/$(date +%Y%m%d)"
mkdir -p "$BACKUP_DIR"

if [ -f "$CLAUDE_FILE" ]; then
  TIMESTAMP=$(date +%H%M%S)
  BASENAME=$(basename "$CLAUDE_FILE")
  cp "$CLAUDE_FILE" "$BACKUP_DIR/${BASENAME}.${TIMESTAMP}.bak"
  echo "Backup criado: $BACKUP_DIR/${BASENAME}.${TIMESTAMP}.bak"
fi

exit 0

💡 Variaveis de Ambiente

$CLAUDE_FILE

Arquivo sendo editado

$CLAUDE_ACTION

Tipo de acao (edit, create, delete)

🔔 Hook post-edit: Notificacoes

Hooks post-edit sao ideais para notificacoes, logging e integracoes que nao devem bloquear o fluxo de trabalho.

Exemplo: Notificacao Slack

#!/bin/bash
# .claude/hooks/post-edit.sh

SLACK_WEBHOOK="$SLACK_CLAUDE_WEBHOOK"
PROJECT_NAME=$(basename "$(pwd)")

curl -X POST "$SLACK_WEBHOOK" \
  -H "Content-Type: application/json" \
  -d "{
    \"text\": \"🤖 Claude editou arquivo\",
    \"blocks\": [{
      \"type\": \"section\",
      \"text\": {
        \"type\": \"mrkdwn\",
        \"text\": \"*Projeto:* $PROJECT_NAME\n*Arquivo:* $CLAUDE_FILE\n*Acao:* $CLAUDE_ACTION\"
      }
    }]
  }"

Exemplo: Log de Auditoria

#!/bin/bash
# Log todas edicoes em arquivo JSON

LOG_FILE=".claude/audit-log.jsonl"

echo "{
  \"timestamp\": \"$(date -Iseconds)\",
  \"file\": \"$CLAUDE_FILE\",
  \"action\": \"$CLAUDE_ACTION\",
  \"session\": \"$CLAUDE_SESSION_ID\"
}" >> "$LOG_FILE"

Casos de Uso

  • • Notificacao em Slack/Teams
  • • Log de auditoria
  • • Trigger de CI/CD
  • • Sincronizacao com ferramentas

Evitar em post-hooks

  • • Operacoes lentas (> 3s)
  • • Modificar o arquivo editado
  • • Dependencias de rede criticas
  • • Logica que deveria bloquear

🛡️ Hook pre-bash: Seguranca

O hook pre-bash e sua ultima linha de defesa antes de Claude executar comandos no terminal. Use para bloquear comandos perigosos.

Exemplo: Bloquear comandos destrutivos

#!/bin/bash
# .claude/hooks/pre-bash.sh
# Variavel: $CLAUDE_COMMAND

BLOCKED_PATTERNS=(
  "rm -rf /"
  "rm -rf ~"
  "rm -rf \$HOME"
  "> /dev/sda"
  "mkfs"
  "dd if="
  ":(){ :|:& };:"
  "chmod -R 777 /"
)

for pattern in "${BLOCKED_PATTERNS[@]}"; do
  if [[ "$CLAUDE_COMMAND" == *"$pattern"* ]]; then
    echo "BLOQUEADO: Comando potencialmente destrutivo detectado"
    echo "Comando: $CLAUDE_COMMAND"
    exit 1
  fi
done

# Alertar para comandos com sudo
if [[ "$CLAUDE_COMMAND" == *"sudo"* ]]; then
  echo "ALERTA: Comando com sudo detectado - requer aprovacao manual"
  # Nao bloqueia, mas alerta
fi

exit 0

⚠️ Comandos a Bloquear

rm -rf / mkfs.* dd if= > /dev/* chmod 777 fork bomb

💡 Dica Pro

Combine pre-bash hooks com o sistema de permissoes do Claude Code. O hook e uma camada adicional de seguranca, nao um substituto.

📚 Biblioteca de Hooks

Colecao de hooks prontos para usar. Copie, adapte e combine conforme necessario.

Auto-format com Prettier

#!/bin/bash
# post-edit: Formatar arquivo editado

if [[ "$CLAUDE_FILE" =~ \.(js|ts|jsx|tsx|json|css|md)$ ]]; then
  npx prettier --write "$CLAUDE_FILE" 2>/dev/null
  echo "Formatado: $CLAUDE_FILE"
fi

Git auto-stage

#!/bin/bash
# post-edit: Adicionar ao stage automaticamente

if git rev-parse --git-dir > /dev/null 2>&1; then
  git add "$CLAUDE_FILE"
  echo "Staged: $CLAUDE_FILE"
fi

Validacao TypeScript

#!/bin/bash
# pre-edit: Validar que arquivo TS compila

if [[ "$CLAUDE_FILE" =~ \.tsx?$ ]]; then
  npx tsc --noEmit "$CLAUDE_FILE" 2>&1
  if [ $? -ne 0 ]; then
    echo "AVISO: Arquivo tem erros TS (nao bloqueando)"
  fi
fi
exit 0

Organizando Hooks

.claude/hooks/
├── pre-edit.sh      # Orquestrador
├── pre-edit.d/      # Hooks modulares
│   ├── 01-backup.sh
│   ├── 02-protect.sh
│   └── 03-validate.sh
└── post-edit.sh

O orquestrador pode executar todos os scripts em pre-edit.d/ em ordem.
